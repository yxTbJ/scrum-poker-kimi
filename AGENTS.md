# AGENTS.md

## Project Overview

Веб-приложение для скрам-покера (planning poker): React-клиент + Node.js/WebSocket-сервер с онлайн-комнатами и синхронизацией голосов в реальном времени. Монорепозиторий на npm workspaces.

**Стек:**
- Сервер: Node.js (ESM), `node:http` + `ws` (без фреймворков), состояние комнат в памяти
- Клиент: React 18 + Vite, прокси `/api` и `/ws` на сервер в dev-режиме
- Тесты: встроенный `node:test` (unit + интеграция двух WS-клиентов), без внешних тестовых фреймворков
- Запуск: `docker compose up --build` (единый образ: сервер раздаёт собранный клиент)

## Commands

- `npm install` — установка зависимостей всех воркспейсов
- `npm run dev` — dev-режим: сервер на :4000 (с автоперезапуском), клиент на :5173
- `npm run build` — сборка клиента в `client/dist`
- `npm start` — продакшн-режим: сервер раздаёт `client/dist` на :4000
- `npm test` — тесты всех воркспейсов (фактически — серверные)
- `docker compose up --build` — полный запуск в контейнере на :4000

## Code Style Guidelines

- Сервер и клиент — ES-модули (`"type": "module"`), клиентные JSX-файлы
- Доменная логика сервера (`server/src/rooms.js`) отделена от транспорта (`server/src/app.js`): store — чистые функции, возвращающие строку ошибки либо null
- Пользователю показываем русские сообщения об ошибках (и в REST, и в WS)
- Без TypeScript, без линтера — придерживаться существующего стиля файлов
- Сообщения протокола: `{type, ...}` JSON; сервер шлёт `state` (полное состояние комнаты) после каждого изменения и `error` при отказе; действия: `start_session`, `end_session`, `vote {value}`, `clear_vote`, `reveal`, `reset`, `update_deck {deck}`

## Testing Instructions

- Тесты лежат в `server/test/`, запускаются через `npm test` (== `node --test`)
- `deck.test.js` — unit-тесты валидации набора карт и имён
- `integration.test.js` — поднимает сервер на эфемерном порту и гоняет сценарий двух WS-клиентов по критериям готовности
- Важно: в after-хуке все сокеты рвутся (`wss.clients.terminate()` + `closeAllConnections()`), иначе `server.close()` виснет вечно и процесс теста не завершается
- В `waitFor` всегда передавать `after` (позиция в истории сообщений), если предикат может совпасть со старым состоянием

## Security Considerations

- Секреты не коммитить: в репозитории нет `.env`, ключей и паролей; аутентификация — по непредсказуемым токенам в памяти (при рестарте сервера комнаты и токены сбрасываются)
- Валидация на сервере обязательна: набор карт (целые 1–100, без дубликатов), имя (непустая строка ≤ 50), голос — только из набора комнаты, reveal/reset/update_deck — только администратор
- Ввод пользователя не доверять: JSON-тела ограничены по размеру, пути статики проверяются на выход за `client/dist`
- Зависимости зафиксированы в `package-lock.json` (npm ci в Dockerfile)
