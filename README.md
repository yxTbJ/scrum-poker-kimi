# Скрам-покер

Веб-приложение для planning poker: React-клиент + Node.js/WebSocket-сервер. Комнаты с синхронизацией в реальном времени, роли администратор/участник, настраиваемый набор карт.

## Возможности

- Комнаты с кодом входа и ссылкой-приглашением
- Обязательный ввод имени и роли (разработчик / QA / остальные сотрудники) для всех участников
- Подсчёт голосов отдельно по ролям: при вскрытии видны среднее общее и среднее по каждой роли; диаграммы переключаются между группами (все / конкретная роль)
- Роли: администратор (создатель комнаты) голосует, вскрывает карты, начинает новый раунд и настраивает набор; участник только голосует
- Набор карт: по умолчанию целые числа 1–30; администратор может убирать и добавлять карты (целые числа 1–100, без повторов); изменение набора сбрасывает голоса
- Среднее значение при вскрытии карт
- Диаграммы при вскрытии: вертикальные столбики и круговая с процентами
- Аватарки участников с инициалами — генерируются локально из id, без внешних сервисов
- Сессии: администратор запускает («Начать сессию») и завершает («Закончить сессию») голосование; карты доступны только во время сессии, набор карт блокируется на её время
- Каждый участник может сбросить свой выбор, вернув статус «думает»
- Закрытие вкладки удаляет участника из комнаты (с паузой 30 с на переподключение); после вскрытия карт отключившийся участник сохраняется вместе с голосом (он уже засчитан в результаты), в новом раунде такие «призраки» удаляются; уход администратора (пока карты не вскрыты) завершает комнату для всех
- Отключённый участник помечается иконкой «нет соединения» (в списке и на вскрытых карточках); кнопка «Покинуть комнату» возвращает на стартовый экран (выход администратора закрывает комнату для всех)

## Fly.io (PaaS, деплой из Dockerfile)

В репозитории готовый `fly.toml` (регион Варшава, 512 МБ, авто-stop выключен — состояние в памяти). Приложение будет доступно по адресу `https://<имя-приложения>.fly.dev` с автоматическим HTTPS.

```bash
winget install --id Fly-io.flyctl        # или: iwr https://fly.io/install.ps1 -useb | iex
fly auth login                           # вход через браузер
git clone https://github.com/yxTbJ/scrum-poker-kimi.git
cd scrum-poker-kimi
fly launch    # подхватит существующий fly.toml; имя/регион можно оставить как есть
fly scale count 1                        # строго одна машина (состояние в памяти)
fly deploy
```

Проверка: `curl https://scrum-poker-kimi.fly.dev/api/health` → `{"ok":true}`. Обновления — `git pull && fly deploy`.

## Автодеплой из GitHub

Репозиторий подключен к приложению через интеграцию Fly.io (GitHub App): **каждый пуш в `main` автоматически деплоится** на Fly, статус виден в дашборде Fly и в разделе GitHub → Actions/Checks. Действий не требуется. Помните: деплой пересоздаёт машину — комнаты сбрасываются, деплойте между сессиями.

## Деплой на Яндекс Cloud (грант для новых аккаунтов)

ВМ в Yandex Cloud — это VPS с поминутной оплатой. Нужны: аккаунт Яндекс ID (консоль: console.yandex.cloud), платёжный аккаунт со стартовым грантом и домен с A-записью на IP ВМ.

```bash
# 1. Compute Cloud → Виртуальные машины → Создать ВМ:
#    имя scrum-poker, образ Ubuntu 24.04, минимум 2 vCPU / 1–2 ГБ RAM,
#    диск 10 ГБ network-hdd, публичный IP «Автоматически» (бесплатный динамический),
#    в поле SSH-ключа — ваш ~/.ssh/id_ed25519.pub
#    (ключ создать заранее: ssh-keygen -t ed25519)
#    Если в сети включены группы безопасности — разрешить входящие 22, 80, 443.

# 2. Подключение и Docker
ssh -i ~/.ssh/id_ed25519 ubuntu@IP_ВМ
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # перелогиниться

# 3. Код и запуск
sudo apt update && sudo apt install -y git
git clone https://github.com/yxTbJ/scrum-poker-kimi.git /opt/scrum-poker-kimi
cd /opt/scrum-poker-kimi
nano Caddyfile                 # poker.example.com → ваш домен
docker compose -f docker-compose.prod.yml up -d --build
```

Проверка: `curl https://ваш-домен/api/health` → `{"ok":true}`. Обновления: `git pull && docker compose -f docker-compose.prod.yml up -d --build`.

Нюансы: динамический IP сменится при пересоздании ВМ (для боевого домена берите статический IP, ~200 ₽/мес); остановленная ВМ не списывает CPU/RAM, но диск и IP оплачиваются; следите за расходом гранта в разделе «Биллинг → Гранты». Без домена можно быстро проверить по HTTP: `docker compose up -d --build` и открыть `http://IP:4000` (кнопка копирования ссылки без HTTPS работать не будет).



Понадобятся: VPS с Ubuntu 24.04 (минимальный тарифа хватит) и домен с A-записью на IP сервера.

```bash
# 1. На сервере: Docker
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER   # перелогиниться

# 2. Залить код проекта в /opt/scrum-poker (git clone или scp, см. ниже)
# 3. В Caddyfile заменить poker.example.com на свой домен

# 4. Запуск
cd /opt/scrum-poker
docker compose -f docker-compose.prod.yml up -d --build
```

Caddy сам получит сертификат Let's Encrypt, как только домен начнёт резолвиться в IP сервера (нужны открытые порты 80/443). Проверка: `curl https://ВАШ-ДОМЕН/api/health` → `{"ok":true}`.

Перенос кода на сервер без GitHub (с машины с проектом):

```bash
tar czf /tmp/scrum-poker.tar.gz --exclude=node_modules --exclude=.git .
scp /tmp/scrum-poker.tar.gz root@IP_СЕРВЕРА:/tmp/
ssh root@IP_СЕРВЕРА "mkdir -p /opt/scrum-poker && tar xzf /tmp/scrum-poker.tar.gz -C /opt/scrum-poker"
```

Обновление после правок кода: перезалить код и повторить шаг 4.

## Тесты

```bash
npm test
```

Включает unit-тесты валидации набора карт и интеграционный тест двух клиентов через WebSocket (сценарий: создание комнаты → вход по коду → настройка набора → голосование → отказ в правах участника → вскрытие → среднее → новый раунд).

## Структура

```
server/            Node.js: http API + WebSocket, состояние комнат в памяти
  src/rooms.js     доменная логика: комнаты, роли, валидация набора карт
  src/app.js       HTTP-маршруты, статика клиента, WS-протокол
  test/            node:test — unit + интеграция
client/            React + Vite
  src/App.jsx      экран входа, восстановление сессии по ?room=КОД
  src/RoomScreen.jsx  стол, участники, колода, панель администратора
  src/DeckSettings.jsx настройка набора карт (только администратор, вне сессии)
  src/VoteChart.jsx  вертикальные столбики распределения голосов
  src/PieChart.jsx   круговая диаграмма с процентами
```

## Протокол

- `POST /api/rooms` `{name, jobRole}` → `{code, token, state}` — создание комнаты (создатель = администратор); `jobRole` обязателен: `developer` | `qa` | `other`
- `POST /api/rooms/:code/join` `{name, jobRole}` → `{token, state}` — вход участника
- `WS /ws?token=…` — JSON-сообщения: клиент → `start_session`, `end_session`, `vote` `{value}`, `clear_vote`, `reveal`, `reset`, `update_deck` `{deck}`, `leave` (выход: участника удаляют сразу, выход администратора закрывает комнату); сервер → `state` (после каждого изменения; участники содержат `connected` — false при отсутствии соединений), `error`, `room_closed` (комната удалена, например уход администратора). `state` включает `sessionActive`: голосование возможно только во время активной сессии, `update_deck` — только вне её. При закрытии последней вкладки участника сервер удаляет его из комнаты после паузы `disconnectGraceMs` (по умолчанию 30 с; в тестах задаётся маленьким значением)

Порт сервера задаётся переменной `PORT` (по умолчанию 4000).
